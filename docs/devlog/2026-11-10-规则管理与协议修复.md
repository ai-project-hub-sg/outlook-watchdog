# 规则管理 CRUD + c6/c7 修复 + 调度重构

- 日期：2026-11-10
- 分支：main
- 类型：feat
- 相关 commit：a48cdfc（probe 修复）a0f5c62（调度）0c9dbf1（通道路由）本次

## 1. 背景

- 真实联调发现 c6 IMAP 认证失败：checkProto 用**裸 scope 名**兑换，
  token 服务端不认；SMTP 探测 Hello 顺序错。c7 对个人邮箱恒被微软禁。
- 用户提出调度过密：核心检查 15min 太频繁，真实发信应自适应降频。
- 用户提出核心诉求：**在本项目内直接管理各邮箱的转发规则**，
  免去逐个登录 Outlook 设置。

## 2. 修改情况

- 代码：
  - `internal/check`：协议兑换改全限定 scope（outlook.office.com/*）；
    535 SmtpClientAuthentication disabled → unavailable/smtp_disabled；
    c4/c8 限频接入 `dueRealMail`（核心健康 24h±2h / 异常 8h±1h）；
    `StableOffset` FNV-1a 账号相位
  - `internal/sched`：调度改 per-account 相位模型（槽起点+相位+微扰），
    间隔默认 60min
  - `internal/graph`：`mutate` 通用写 + CreateRule/UpdateRule/DeleteRule
  - `internal/msauth`：`RuleWriteScope` 可选附加档
  - `internal/classify`：MessageRule 补 ID/Sequence 字段与地址访问器
  - `internal/web`：`/account/rules` CRUD 页面+3 个写 handler；
    授权向导/重新授权加「附加规则管理权限」勾选；通道列表脱敏路由
  - `internal/store`：migration 003 `rule_ops` 审计表
- 口径：smtp_disabled 新增 unavailable 分类（个人邮箱平台限制）

## 3. 完成情况

- 已完成：规则管理全链路（列表/新建/启停/编辑/删除/审计/基线自动重建）、
  授权档勾选、probe 修复、调度错峰、通道测试回显路由
- 待真实联调（用户回来后）：规则管理档授权 + CRUD 实测
- 遗留：复杂条件（fromAddresses 等表单外字段）编辑保存会被表单值重写，
  页面已用 * 标记提示

## 4. 影响

| 对象 | 变更前 | 变更后 |
|------|--------|--------|
| c6/c7 | 裸 scope 兑换→auth_failed | 全限定兑换→xoauth2 ok（c6 实测通过） |
| c7 个人邮箱 | fail/auth_failed | unavailable/smtp_disabled（degraded） |
| 调度 | 15min 全局等间隔 | 60min 每账号相位错峰 |
| c4/c8 | c8 仅 30min 硬限频，c4 无限频 | 自适应：健康≈1次/天，异常≈3次/天 |
| 规则 | 只读审计 | 可 CRUD（写需附加 scope） |
