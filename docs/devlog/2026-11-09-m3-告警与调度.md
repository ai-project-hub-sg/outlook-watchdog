# M3：告警通道、迁移告警与调度循环

- 日期：2026-11-09
- 分支：main
- 类型：feat
- 相关 commit / tag：M3 提交

## 1. 背景

按 design.md 里程碑推进 M3：独立渠道告警（webhook + SMTP）、状态迁移去抖告警、interval+jitter 常驻调度。目标：CLI 形态即可投入真实监控使用。

## 2. 修改情况

- 代码：
  - `internal/store`：新增 notify_channels/alert_events DAO（含 ListAlerts）、MarkAlerted
  - `internal/notify`：webhook（JSON POST+可选 token）与 smtp（465 隐式 TLS / 587 STARTTLS、Q-encoding 主题、PlainAuth）两种 Sender；`DecideAlert` 纯函数（迁移+阈值+去重+恢复判定）；`Dispatch` 分发与事件落库
  - `internal/sched`：Scheduler（settings 读 interval_min/jitter/fail_threshold 带默认）、RunOnce（捕获 prev→迁移判定→Dispatch）、Loop（interval±jitter、ctx 取消）
  - `internal/check`：Outcome 增 Err；updateState 非 ok 全计入连续失败（failed/unknown/degraded）
  - `cmd/watchdog`：新增 run/channel(add webhook|smtp|list|remove)/test-notify/settings/alerts 子命令；check --once 复用 sched.RunOnce 使手动检查同样走迁移告警
- 检查项 / 口径：告警口径实现 status-codes §5（迁移才告警、连续 N 轮确认、恢复通知）
- 配置 / 文档：scripts/test-rule.ps1（负面对账辅助：Graph API 建/删测试规则）

## 3. 完成情况

- 已完成：全链路**真实闭环**验证（见 §5）；DecideAlert 9 用例单测
- 未完成：serve/WebUI（M4/M5）、IMAP/SMTP 探测与 roundtrip（M6）、163 授权码最初误用 login 密码的坑（已换授权码解决）
