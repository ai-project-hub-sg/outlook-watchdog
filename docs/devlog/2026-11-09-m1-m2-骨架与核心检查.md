## 1. 背景

## 2. 修改情况

- 代码：
  - `internal/config`：引导配置 + `.env` 加载（不覆盖已有变量）+ `${ENV}` 展开
  - `internal/store`：SQLite（modernc.org/sqlite）+ `migrations/001_init.sql` + 全表 DAO；`trigger`/`check` 为 SQLite 保留字，列名定为 `source`/`check_name`
  - `internal/classify`：token grant 分类器（含 banned/token_invalid/reauth/config/throttled/network 七类）+ `messageRules` 规范化与基线 diff（可疑转发/隐藏规则→fail，良性变化→degraded）
  - `internal/msauth`：refresh_token grant（RT 轮换回调）+ device code flow（get-token 用）
  - `internal/graph`：/me、messages?$top=1、messageRules、sendMail 最小客户端
  - `internal/check`：单账号管线编排（C1 短路 → C2/C3 → C5 → 聚合落库 + RT 轮换持久化 + 状态迁移）
  - `cmd/watchdog`：CLI 子命令 check/snapshot/status/account(add|list|remove)/get-token/migrate/version；RT 只经 `--rt-env` 环境变量传入，输出全程脱敏
- 检查项 / 口径：实现 C1/C2/C3/C5；C4/C6/C7/C8 未实现（对应设计默认关闭项）
- 配置 / 文档：`config.example.yaml`；README 补使用说明前置；`.env` 凭据纪律写入 AGENTS.md §4.1.6

## 5. 验证

- 测试：`go test ./...` 全绿（classify 6 fixture + 8 状态矩阵 + 7 聚合用例；rules diff 6 用例；check 4 端到端）
- 对账：
  - 假 RT 真实 grant 验证全链路（invalid_grant→token_invalid 判定正确、exit code 正确、输出脱敏）
  - **真实账号对账（2026-11-09 完成）**：device code flow + Graph PowerShell client_id（`14d82eec-...`，用户已自行 consent `Application.ReadWrite.All`，连带邮件 scope 一并授权成功）取得 RT → `account add`（RT 经 `--rt-env` 从 .env 注入，未明文经 argv）→ `snapshot` 建基线（0 规则）→ `check --once` 四项全 pass → 状态 ok、exit 0
  - 发现的坑：① Azure CLI client_id 对消费级 Graph 邮件 scope 无法 consent（第一方应用预授权限制）；② Connect-MgGraph 对 MSA 账号内部轮换设备码导致反复超时——最终改用 watchdog 自带 get-token + Graph-PS client_id 一步拿到全 scope RT
  - 注意：该 RT 的 scope 包含 Application.ReadWrite.All，权限偏大；生产建议未来注册专用 app 仅要邮件 scope（decision 候选）
