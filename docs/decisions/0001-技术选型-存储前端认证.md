# 0001 技术选型：存储、WebUI 形态、认证

- 日期：2026-11-09
- 状态：已确认（需求方选定）

## 背景

需求在纯 CLI 看门狗之上追加"完整管理后台"WebUI（大盘、账号管理、调度/告警配置、日志查询、运行状态），账号规模预设为几个~几十个，部署为局域网/VPS 单管理员访问。

## 决策

1. **SQLite 作为运行时唯一权威数据源**（`data/watchdog.sqlite`，pure-Go `modernc.org/sqlite`，WAL）：账号、状态、检查历史、告警事件、告警渠道、调度参数、session 全部入库；`config.yaml` 退化为引导配置（listen/data_dir/可选 admin 密码注入）。
   - 备选：config.yaml + state.json + jsonl。被否原因：业务配置需在线修改，yaml 回写丢注释且易双写漂移；jsonl 不利于日志页筛选分页。
   - 备选：mattn/go-sqlite3。被否原因：cgo 依赖破坏单静态二进制与交叉编译。
2. **前端 Go embed + html/template + vendored htmx**：服务端渲染 + 局部刷新，无 node 构建链，保持单二进制交付。
   - 备选：Vue/React SPA。被否原因：引入第二语言栈与构建链，对本规模与需求收益不足。
3. **单管理员密码认证**：argon2id/bcrypt 哈希入库；session token cookie（HttpOnly+SameSite=Lax）；非 GET 校验 CSRF token；登录限速。
   - 备选：HTTP Basic / 多用户 / OIDC。被否原因：Basic 无法吊销与限速语义差；多用户与 OIDC 超出当前需求。
